# План телеграм-бота для студии

Статус: этапы 1–3 сделаны, лагерь прикручен, преподавателю пишем отдельно.
Дата: 2026-09-24.

Решения приняты: канал — телеграм, им пользуются все русскоязычные
родители. Запись финансовых последствий пока не имеет: отмена ничего не
стоит, неявка ничего не стоит. Цель бота — приучить записываться, а
рычаг — места: кто не записался, тот может не попасть.

Решено 2026-09-22 по цифрам из раздела 2: честное число мест — **9**,
проставлено всем занятиям (у лагеря своя вместимость, 8). Вариант
мягкий: никого не разворачиваем, бот показывает число свободных мест и
ничем не грозит.

---

## 1. Зачем бот, если кабинет уже есть

Записаться можно и сейчас: `/account/calendar`, кнопка у каждого имени,
`setBooking` в `src/lib/studio.ts`. Бот этих экранов не добавляет.

Бот добавляет одно: **вопрос приходит сам**. Кабинет пассивен — родитель
должен вспомнить, открыть, нажать. Письмо в Gmail тонет. Сообщение в
телеграме читают в тот же вечер. Вся ценность затеи в этом, и значит
главный экран бота — не список занятий, а вечернее «Маша завтра придёт?»
с двумя кнопками.

Бизнес-логики бот не приносит вообще. Он вызывает те же функции, что и
кабинет, и пишет в те же таблицы:

| Что нужно боту | Что уже написано |
|---|---|
| неделя семьи | `slotsForUser` (studio.ts:892) |
| запись и отмена | `setBooking` (studio.ts:550), места считаются в транзакции |
| сколько мест осталось | `SlotRow.capacity` и `SlotRow.taken`, формула в `SlotList.seats` |
| долги семьи | `unpaidCharges` (studio.ts:436) |
| ссылка на оплату | `startPayment`, `checkoutUrl` (billing.ts) |
| абонемент кончается | `passBalances`, `PASS_WARN_DAYS` |
| не послать одно и то же дважды | образец `mail_log` в 013_mail.sql |

Отсюда правило, которое нельзя нарушать ни на одном этапе: **у бота нет
своих данных и своей логики**. Он транспорт. Любая попытка завести
«таблицу бота» означает, что появился второй источник правды, и кабинет с
журналом Вари начнут расходиться.

## 2. Что показала боевая база

Замер 2026-09-22, последние 45 дней.

| Что | Число |
|---|---|
| Вместимость групп | проставлена везде: 6 у всех занятий, 8 у лагеря |
| Явок | 38, из них **записаны были 13** |
| Активных детей | 21 из 27 |
| Родителей | 23, ник телеграма заполнен у 5 |
| Долги | 7 начислений, 4 должника, 700 ₪ |
| Занятий вперёд | 82, до 31 декабря |

Отдельно — заполняемость. Вторник 15 сентября: мест 6, пришло **9**.
Четверг 10 и 17 сентября: пришло ровно 6 из 6. Вторник 8 сентября: 4.

Отсюда три вывода, и они важнее всего остального в этом документе.

**Дефицит настоящий.** Занятия упираются в потолок и переезжают через
него. Значит «можешь не попасть» — не выдуманный рычаг, а описание того,
что уже происходит. Это сильный аргумент за бота.

**Записью пользуется треть.** Из 38 пришедших записаны были 13. Две трети
приходят ногами. Ровно эту щель бот и закрывает, и другого способа её
закрыть нет: кабинет открыт всем уже сейчас, и его не открывают.

**Сегодня система наказывает того, кто записался.** Вместимость
проверяется только в `setBooking` (studio.ts:570), а на двери не
проверяется ничем: `sessionRoster` пускает в журнал всех, кто подходит
занятию по типу, и это сделано намеренно (studio.ts:722). Добросовестный
родитель, который открыл кабинет седьмым, получит «мест нет». Тот, кто
просто привёл ребёнка, станет девятым и попадёт. Пока это так, бот будет
усиливать не ту привычку, а первый же отказ в записи обесценит всё
остальное, что бот говорит.

Чинить это надо до этапа 3, и это два отдельных решения Вари.

**Первое: какое число честное.** Если в комнату помещается 9 — в базе
должно стоять 9, иначе `setBooking` врёт про отсутствие мест там, где они
есть. Если помещается 6 — значит два занятия в сентябре прошли с
перегрузом, и это стоит знать отдельно.

**Второе: что происходит с незаписавшимся.** Вариантов два.

*Мягкий, рекомендуемый для старта.* Никого не разворачиваем, бот не
угрожает, а показывает число, которое код и так считает: «осталось 3
места». Дефицит, названный цифрой, учит записываться, и поймать бота на
вранье невозможно в принципе.

*Жёсткий.* Место без записи не гарантируется, и один раз это применяется
на деле. Одного раза достаточно: об этом узнают все родители в тот же
день. Без этого одного раза жёсткий вариант не включается вообще, потому
что за сентябрь никого не развернули ни разу.

Начать с мягкого и перейти к жёсткому можно. Наоборот — нет: бот, который
пригрозил и не исполнил, дальше читается как шум.

## 3. Что добавляется в базу

Миграция `015_telegram.sql`, три вещи и ни одной лишней.

```sql
-- Ник и chat_id — разные вещи. Ник нужен Варе, чтобы написать человеку
-- руками из /admin/studio/people. Боту он бесполезен: по нику писать
-- нельзя, адресом является только chat_id, и он появляется лишь после
-- того, как человек сам нажал Start.
alter table users add column if not exists tg_chat_id bigint unique;

-- Привязка. Одноразовый токен живёт в ссылке t.me/<bot>?start=<token>,
-- в базе лежит хеш — как у login_codes, по тем же причинам.
create table tg_links (
  id         uuid primary key default gen_random_uuid(),
  user_id    uuid not null references users(id) on delete cascade,
  token_hash text not null unique,
  expires_at timestamptz not null,
  used_at    timestamptz,
  created_at timestamptz not null default now()
);

-- След отправленного. Крон может сработать дважды, деплой может
-- перезапустить рассылку; без этого родитель получит вопрос два раза.
create table tg_log (
  campaign  text not null,
  chat_id   bigint not null,
  sent_at   timestamptz not null default now(),
  primary key (campaign, chat_id)
);
```

Ни записей, ни ответов бот отдельно не хранит: «придёт» — это строка в
`bookings`, та же самая, что ставит кабинет.

## 4. Этапы

### Этап 1. Труба и привязка — сделано 2026-09-22

Ничего не рассылаем, проверяем, что сообщение доходит и человек узнан.

- Бот в BotFather, токен в `TELEGRAM_BOT_TOKEN`, отдельный секрет вебхука
  в `TELEGRAM_WEBHOOK_SECRET`.
- `/api/telegram/route.ts`, `runtime = 'nodejs'`. Первым делом сверяем
  заголовок `X-Telegram-Bot-Api-Secret-Token` с секретом: вебхук открыт
  всему интернету, и без проверки апдейты шлёт кто угодно. Отвечаем `200`
  всегда, даже на свою ошибку, иначе Telegram будет ретраить час.
- В `/account/profile` кнопка «Подключить телеграм»: заводим строку в
  `tg_links`, ведём на `t.me/<bot>?start=<token>`. Токен одноразовый, 15
  минут, длина укладывается в лимит payload (64 символа).
- `/start <token>` → находим живой токен, пишем `tg_chat_id`, гасим
  `used_at`. Привязка только так. Ни по email, ни по нику, ни по номеру:
  иначе к чужой семье с детьми и долгами привяжется посторонний.
- Одна команда «Моя неделя» — текстом, из `slotsForUser`.

### Этап 2. Запись кнопками — сделано 2026-09-22

Неделя приходит одним сообщением с кнопками под ним. Нажатие →
`callback_query` → `setBooking` → перерисовка того же сообщения.
Гонок нет: место занимает `setBooking` с `for update`, а не экран.

Три вещи по дороге вышли не так, как рисовались в плане.

**На кнопке состояние, а не действие.** В кабинете кнопка говорит, что
случится от нажатия («Записать»), а состояние стоит у имени («придёт»).
В боте кнопка — единственное, что можно нажать, и читается она вместе
со строкой над собой. Поэтому на ней галочка: `✓ вт 22 · Отто` значит
«записан», нажатие переключает.

**Два uuid не влезают в кнопку.** `callback_data` — 64 байта, а
`session_id` и `participant_id` текстом занимают 72. Кладём их сырыми
байтами в base64url, по 22 знака: вместе с пометкой действия выходит 48.

**Кнопки по две в ряд.** У семьи с тремя детьми их на неделю выходит
дюжина, и столбиком сообщение превращается в простыню.

Права проверяются при нажатии, а не при рисовании: кнопка могла быть
нарисована час назад. Участник должен принадлежать семье — проверка та
же, что в кабинете; записаться в прошлое нельзя; на занятие без мест
кнопки просто нет, но свою запись снять можно всегда.

### Этап 3. Вечерний вопрос — сделано 2026-09-22

Расписание Vercel зовёт `/api/cron/telegram-ask` раз в сутки. Роут
открыт интернету, поэтому сверяет `CRON_SECRET`, который Vercel сам
подставляет в заголовок. **Секрета нет — рассылка не работает вовсе**:
иначе запустить её смог бы кто угодно и сколько угодно раз.

**Кому.** Занятие завтра есть, записи на него нет, и есть основание
ждать: ребёнка приводили на это же занятие в последние две недели или
этот день отмечен у него в профиле. Первого хватает тем, кто ходит и
профиль не заполнял, второго — новичкам, которых в журнале ещё нет.
Решено по цифрам: приоритетные дни заполнены у 21 участника из 52, а
ходили за две недели 19 человек — списки разные, и брать надо оба.

**Записавшимся не пишем ничего.** Вопрос без смысла обесценивает все
остальные, и через месяц их перестанут читать.

**Сообщение короткое,** в отличие от недели: одно занятие, семья под
ним, по две кнопки на каждого — «придёт» и «не придёт». Оно приходит
само и вечером, простыня на семь дней тут не к месту. Перерисовывается
оно в себя: кнопка помнит, из какого сообщения нажата, и подменять
вопрос недельным списком нельзя.

**Отказ — это ответ.** «Не придёт» заводит отменённую строку в
`bookings`, даже если записи не было, и по ней «сказал нет» отличимо от
«промолчал». Нигде больше эта строка не считается: и места, и журнал
смотрят только на `booked`. Ради этого же в `bookings` появилась
`updated_at` — без неё ответ сегодня вечером неотличим от записи
недельной давности.

**Молчание ничем не наказывается.** Пришёл без записи — всё как раньше,
Варя отмечает его в «Остальных».

**Дважды не спросим:** отметка в `tg_log` ставится до отправки, а если
сообщение не ушло — снимается, чтобы следующий запуск попробовал снова.

**Время.** `0 16 * * *` UTC, то есть 19:00 по Израилю летом и 18:00
зимой: расписание Vercel не знает про часовые пояса. Менять — в
`vercel.json`. На тарифе Hobby задание запускается раз в сутки и может
сработать в любой момент своего часа, так что «ровно в 19:00» обещать
нельзя.

**Во время лагеря вопрос почти молчит:** обычных занятий на эти дни
нет, а смену бот спрашивает отдельным сообщением по запросу, не
рассылкой.

### Этап 4. Долги

Независим от первых трёх, можно двигать вперёд. Раз в неделю: строки из
`unpaidCharges` и кнопка со ссылкой PayPlus через `startPayment`. Решений
не требует и делается за вечер, но денег на кону немного: 700 ₪ у четырёх
семей. Это удобство для Вари, а не главный приз.

### Лагерь в боте — сделано 2026-09-22

Смена приходит **отдельным сообщением**, по одному на каждую: она идёт
подряд много дней и решается один раз, а неделя живёт своим чередом. В
общем сообщении десять дней лагеря заслонили бы четыре занятия. Когда
смена кончится, сообщение перестанет приходить само — будущих дней не
останется, выключать нечего.

Текст у смены устроен иначе, чем у недели. Какой день и кто на него
идёт, видно по кнопкам, и повторять это ещё и текстом значит получить
полотно в полсотни строк. Поэтому текстом остаётся только то, чего на
кнопке не написать: цена дня, с какого дня выгоднее пакет, сколько мест
свободно по каждому дню и сколько дней уже отмечено у каждого ребёнка —
последнее и решает, брать пакет или платить поштучно.

Кнопки у смены идут блоками по человеку, а не вперемешку по дням: родитель
отмечает все дни одному ребёнку подряд, и в списке из тридцати кнопок это
единственный способ не сбиться. В неделе порядок остаётся дневным.

### Преподаватель — сделано 2026-09-24

Варе бот отвечает не тем же, что родителю: своей семьи в студии у неё нет,
она не опекун и сама на занятия не ходит, поэтому родительская неделя у
неё пустая и до этого бот отвечал ей «занятий нет».

Различаем по роли `teacher` и только по ней, без админов: админ — это
Дима, у него в студии свой ребёнок, и подменять ему неделю журналом
незачем. Кто и преподаёт, и водит детей, получит оба сообщения.

**Перенос виден.** Если занятие идёт не в обычное время группы, за
временем стоит «перенесено» — и в сводке, и в напоминании, и в
родительской неделе. Признак строгий: своё время, **отличное** от
обычного. Раньше хватало самого факта, что время задано, и пересохранение
без изменений показывало ложный перенос.

**Три списка, а не один.** «Записались», «обычно ходят, но не отметились»
и «не придут». Вторая строка обязательна, пока записывается треть: на
четверг 24 сентября записаны двое, а обычно ходят четверо, и без неё
сообщение врало бы в полтора раза. Третья строка — то, чего не было
нигде: кто снял запись или ответил боту «не придём».

«Не придут» — только те, кто прямо ответил боту «не придёт» на вечерний
вопрос. Снятая на сайте запись сюда не попадает: это отсутствие записи, а
не обещание не прийти. Статуса `cancelled` для такого различения мало —
он получается в обоих случаях, — поэтому в `bookings` появилась
`declined_at`: ставится только из вечернего вопроса и снимается сама,
когда человек записывается обратно.

Пока вечерний вопрос ни разу не срабатывал, эта строка не появится вовсе.
Это не поломка, а верный ответ: боту ещё никто не отказывал.

Заканчивается сообщение пожеланием, каждый раз другим. Ссылки на журнал в
нём нет: одна и та же строчка каждое утро через неделю читается как
подпись в подвале.

**Когда.** Сводка на день в 07:30 и напоминание за час до каждого
занятия. Сводка дублируется суперадмину отдельным сообщением с пометкой
«Копия сводки»: она обращается к Варе по имени, и без пометки читалась бы
как письмо не по адресу. Роль преподавателя для этого не годится — она
подменила бы ему родительскую неделю журналом и прислала бы ещё и
напоминания за час, которые ему не нужны. Плюс по запросу: Варя пишет боту что угодно и получает состав на
текущий момент — это свежее любой рассылки и не требует расписания вовсе.

**Чем зовётся.** Роут сам считает по часам студии, что сейчас пора,
поэтому переход на зимнее время ничего не ломает, а окно `[75..30]` минут
до начала терпит опоздания триггера. Триггеров три, и все ведут в
`lib/tg-due`; отметки в `tg_log` не дают отправить дважды, поэтому мешать
друг другу они не могут.

1. **Внешний пингер** (cron-job.org и подобные) — основной. Раз в 15–30
   минут дёргает `/api/cron/telegram-teacher` с ключом `CRON_SECRET`.
2. **Открытие журнала** — подстраховка без чужих сервисов. Варя заходит в
   `/admin/studio` в течение дня, и проверка идёт после ответа страницы,
   не задерживая её. Себя ограничивает через `settings.tg_tick_at`, не
   чаще раза в пять минут, тем же приёмом, что `ensureSessions`.
3. **GitHub Actions** — оказался негодным как основной и оставлен третьей
   дорогой и кнопкой ручного запуска. Замер за первый день: при `*/30`
   расписание дало **два запуска за 13,5 часов** вместо двадцати семи,
   промежуток между ними 4 часа 48 минут. Окно в 45 минут такого не
   переживает, и напоминание в тот день не ушло.

Расписание Vercel не годится вовсе: на Hobby задание идёт раз в сутки и
может сработать в любой момент своего часа.

Отказ объясняет себя: `401` содержит, что именно приехало — заголовка не
было, в нём одно слово вместо «Bearer ключ», или ключ такой-то длины.
Значение не показываем, только способ и длину: без этого внешний сервис
отвечает глухим `401`, и понять, заголовок не дошёл или секрет не тот,
нельзя.

Пингеры, которые не умеют свои заголовки, могут передать слабый ключ в
адресе: `?key=…`. Обычно ключ в адресе — плохо, он попадает в логи; но
этим ключом навредить и нельзя, а сильный в адресе не принимается никогда.

**Ключа два, с разными правами** (`lib/cron-auth`). `CRON_SECRET` умеет
только спросить «что пора»: окна по времени и отметки в `tg_log`
превращают любой лишний вызов в пустой, поэтому его не страшно отдать
внешнему сервису. Немедленная отправка требует `CRON_FORCE_SECRET` и
остаётся у нас; чужим ключом `force` отвечает 403. Второй ключ не задан —
принудительной отправки нет вовсе, и это выбор, а не поломка.

Сводка и напоминание не дублируются: если сводка ушла меньше 90 минут
назад, напоминание по тому же занятию молчит — для лагеря в 9:00 они иначе
пришли бы с разницей в полчаса почти одинаковыми.

**Что именно ушло** лежит в `tg_log.text`: текст складывается туда после
успешной отправки. Пожелание выбирается случайно, а прочитать посланное
ботом у Telegram нельзя — без журнала на вопрос «что получил человек»
ответить нечем, а для сообщений, которые мы посылаем сами, без спроса,
это обязательно. Смотреть: `npm run tg:log:prod`. Ответы на сообщения
родителей в журнал не идут: это переписка, её видит сам человек.

**Руками:** `npm run tg:teacher` — сводка сейчас, `npm run tg:teacher -- next`
— напоминание про ближайшее занятие. Нужен `CRON_SECRET` в
`.env.production.local`. Ответ содержит `tried`, чтобы «не пора» отличалось
от «пора, но не ушло».

**Обращение** взято из кода: преподаватель один и просил звать себя
Варюшей. Появится второй педагог — станет полем.

### Уведомления по событию — сделано 2026-09-24

Расписание GitHub за первые полдня не сработало ни разу, поэтому первыми
сделаны те сообщения, которые запускает человеческое действие: они уходят
всегда и сразу, независимо от крона.

| Событие | Кому | Почему это важно |
|---|---|---|
| занятие отменили, перенесли, вернули | записанным и всем админам | приехать с ребёнком на отменённое занятие хуже любого лишнего сообщения, а `moved` виден только тому, кто сам откроет кабинет |
| родитель заявил оплату | админам | пока заявку не подтвердили, деньги висят незачтёнными |
| деньги зачли, заявку отклонили | родителю | раньше он не узнавал ни о том, ни о другом |
| незакрытые журналы | Варе, в утренней сводке | это не забытая галочка, а непосчитанные деньги |

У админов сообщение своё: в нём весь состав занятия, а не одна семья, и
сказано, кто нажал, — иначе своё действие не отличить от чужого. Тому, кто
нажал, тоже приходит: пусть у обоих будет одна картина. Дважды одному чату
не пишем — админ может оказаться и родителем записанного.

Живёт в `src/lib/notify.ts` и зовётся **из действий**, а не из `studio.ts`
и `billing.ts`: библиотека остаётся операциями над данными. Ни одно
уведомление не имеет права сломать действие, внутри которого позвано —
Варя отменила занятие, и если телеграм лежит, отмена всё равно состоится.

Сборка текста отделена от отправки: текст можно посмотреть, не рассылая.
Адрес сайта приходит аргументом, потому что `siteOrigin` работает только
внутри запроса.

Ложных рассылок нет: «перенесли» и «вернули в расписание» уходят только
если **действующее** время или состояние правда изменились. Сравнение по
`coalesce(s.starts_at, g.starts_at)` — снять переопределение и попасть в
обычное время группы значит не изменить ничего.

### Подтверждение оплаты в боте — сделано 2026-09-24

Заявка приходит Варе карточкой с кнопками, и деньги проводятся не выходя
из телеграма. Два касания, а не одно, и это не лишний шаг:

1. **Чем заплатили.** Способ обязателен и не подставляется, если родитель
   заявил «перевод»: для него это и банк, и биток, и пейбокс, а в чеке это
   три разные вещи. Наличные подставляются первыми — их Варя берёт в руки.
   Ровно то же правило, что на экране «Финансы».
2. **Чек в iCount.** Отдельный вопрос, по умолчанию без чека, как и
   галочка на сайте. Без iCount выбора нет, просто «деньги получены».

Права проверяются при нажатии, а не при рисовании: карточка могла уехать в
чат месяц назад. Проводит деньги только `admin`. Заявку, закрытую с
другого устройства, кнопка не проведёт второй раз — карточка перерисуется
в «эту заявку уже закрыли».

## 5. Чего нельзя сломать

1. Кабинет остаётся полноценным. Бот — второй вход, а не замена: у части
   родителей телеграма всё равно не окажется.
2. Все проверки доступа те же, что в кабинете. `tg_chat_id` даёт только
   `user_id`, дальше семья определяется через `guardians`, как везде.
   Чужих детей бот не показывает никогда.
3. Ник в телеграме (`users.telegram`) не трогаем и не подменяем: он нужен
   Варе, чтобы написать человеку руками.
4. Рассылка идёт последовательно, с паузой. Лимит Telegram около 30
   сообщений в секунду, при десятках семей это не проблема, но очередь
   должна быть предсказуемой, чтобы повтор крона был безопасен.
5. Отписка. Из рассылок бота нужно уметь выйти одной кнопкой, как из
   почтовой. Вопросы про своего ребёнка и свои деньги отпиской не
   отменяются — по тому же правилу, что в `mail.ts`.

## 6. Как включить бота

Этап 1 в коде есть, но без трёх переменных он спит: `isConfigured()`
отвечает «нет», кнопка в профиле уводит на «бот ещё не настроен», а
вебхук отвечает 401 всем подряд.

| Переменная | Что это |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен от BotFather |
| `TELEGRAM_BOT_NAME` | имя бота без «собаки», из него собирается ссылка привязки |
| `TELEGRAM_WEBHOOK_SECRET` | любая длинная случайная строка, сверяется на каждом вызове |
| `CRON_SECRET` | ключ триггера: им можно только спросить «что пора». Его отдают внешнему пингеру |
| `CRON_FORCE_SECRET` | второй ключ, для немедленной отправки. Остаётся у нас; без него `npm run tg:teacher` не работает |

Порядок:

1. Завести бота у BotFather, положить три переменные в Vercel и в
   `.env.production.local`.
2. Накатить миграцию: `npm run migrate:prod`.
3. Задеплоить и зарегистрировать вебхук:
   `npm run tg:setup:prod -- https://www.re-create.art`. Именно `www`:
   голый домен отвечает 307 на канонический, а телеграм редиректы на
   вебхуке не ходит и молча копит очередь. Тот же скрипт без адреса
   показывает, что телеграм думает про вебхук сейчас.

   Этот же шаг нужно повторять всякий раз, когда меняется список
   `allowed_updates` в скрипте: телеграм хранит его у себя и без
   перерегистрации просто не станет присылать новый вид апдейтов.

   Адрес с редиректом скрипт теперь не примет: проверяет его сам и
   называет тот, на который уводит. Накопившуюся очередь по умолчанию
   **не выбрасывает** — она копится ровно тогда, когда вебхук сломан, и
   лежат там живые сообщения родителей. Очистить можно флагом `--drop`.
4. Проверить `/api/health`: `telegram` и `telegramHook` должны стать `true`.
5. Открыть `/account/profile`, нажать «Подключить телеграм», в боте нажать
   «Запустить», написать боту что угодно — он ответит ближайшей неделей.

## 7. Осталось выяснить

1. **Время вечерней рассылки.** 19:00 — догадка, а не решение.
2. **Кого считать «ждём».** Сейчас предлагается приоритетный день или
   посещение на прошлой неделе. Если у Вари другое представление о том,
   кто ходит постоянно, правило нужно поменять до первой рассылки.
3. **Как привести родителей в бота.** Кнопка есть, но ник в телеграме
   заполнен у пятерых из двадцати трёх: сам по себе никто не придёт.
   Проще всего — Варя на занятии показывает ссылку с телефона.
