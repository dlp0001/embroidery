# База

Локально Postgres поднимается докером:

```bash
docker run -d --name recreate-postgres \
  -e POSTGRES_PASSWORD=dev -e POSTGRES_USER=dev -e POSTGRES_DB=recreate \
  -p 5442:5432 postgres:18-alpine
```

Дальше схема и тестовые данные:

```bash
npm run migrate
npm run seed
```

`seed` очищает студийные таблицы и заливает четыре группы, четырёх человек
и историю посещений за месяц. На проде его запускать нельзя.

Миграции лежат в `migrations/`, применяются по имени и только один раз.
Новая миграция — новый файл с номером больше предыдущего.

## Грабли

Перед коммитом проверяйте так:

```bash
npm run verify
```

Это типы плюс полная сборка, но в отдельную папку `.next-verify`.
Обычный `npm run build` пишет туда же, куда `npm run dev`, и рабочий
дев-сервер после него начинает отдавать 404 и 500 на собственные файлы.
Если это уже случилось, помогает перезапуск дев-сервера.

## Что нужно на проде

`DATABASE_URL` и `SESSION_SECRET`. Без них разделы студии показывают
заглушку «раздел ещё не подключён», а курс по вышивке работает как
обычно.

## Neon

Один проект, одна база. Postgres 17 подходит, ничего экзотического схема
не требует: нужны расширения `citext` и `pgcrypto`, оба в Neon есть.

Регион берите ближе к людям и к деплою — для Израиля это Франкфурт
(`aws-eu-central-1`).

Neon даёт две строки подключения:

- **Pooled** (в хосте есть `-pooler`) — её кладём в `DATABASE_URL` на
  Vercel. Приложение живёт в serverless, соединений много и они короткие.
- **Direct** (без `-pooler`) — по ней гоняем миграции: DDL через пулер
  ходит хуже.

Миграции на прод:

```bash
DATABASE_URL='<direct-строка>' npm run migrate
```

`npm run seed` на проде запускать нельзя: он вычищает студийные таблицы.

Ещё нужен `SESSION_SECRET` — длинная случайная строка:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```

## Выкладка со схемой

Если в коммите есть новая миграция, её нужно накатить на боевую базу
**до или сразу после** выкладки, иначе приложение упадёт на первом же
обращении к новой таблице:

```bash
npm run migrate:prod
```

Проверить, что схема догнала код:

```bash
curl -s https://re-create.art/api/health
```

Поле `lastMigration` должно совпадать с последним файлом в
`db/migrations/`.

## Роли

В базе нет ролей по умолчанию: первый вход заводит обычного родителя.
Преподавателя и админа выдают руками:

Чтобы не таскать строку подключения по командам и переписке, положите
её один раз в `.env.production.local` в корне проекта:

```
DATABASE_URL=postgresql://…
```

Файл в `.gitignore`, в репозиторий не попадёт. Дальше команды короткие
и без секретов:

```bash
npm run roles -- acidophline@gmail.com teacher,admin 'Варя Перлина'
npm run roles -- id@perlin.ru superadmin,admin 'Дима'
npm run migrate:prod
```

Скрипт заводит человека, если его ещё нет, и повторный запуск ничего
не ломает.

## Письма

Код входа уходит через Resend. Нужны переменные:

- `RESEND_API_KEY` — обязательна на проде. Без неё письмо не уходит, и
  форма честно говорит об этом, а не делает вид, что отправила.
- `FROM_EMAIL` — необязательна, по умолчанию `info@re-create.art`.
  Домен должен быть подтверждён в Resend.

В разработке ключа нет, письма не шлются, код показывается прямо на
странице входа и подставляется в поле.

## PayPlus

Три переменные, без них оплата картой просто не показывается, а студия
работает как раньше:

- `PAYPLUS_API_KEY` и `PAYPLUS_SECRET_KEY` — уходят заголовками `api-key`
  и `secret-key`.
- `PAYPLUS_PAGE_UID` — идентификатор платёжной страницы из кабинета.
- `PAYPLUS_ENV` — `test` (по умолчанию) или `prod`. Тест ходит на
  `restapidev.payplus.co.il`, бой на `restapi.payplus.co.il`.

Обратный вызов настраивать в кабинете не нужно: адрес передаётся в
каждом запросе полем `refURL_callback` и указывает на
`/api/webhook-payplus`.

Подписи у обратного вызова в документации нет, поэтому его содержимому
мы не верим: по идентификатору переспрашиваем PayPlus через
`/PaymentPages/ipn` и сверяем сумму со своей записью. Повторный вызов
безопасен, платёж применяется один раз.

Идентификатор платёжной страницы можно не искать глазами:

```bash
npm run payplus:pages
```

Команда берёт ключи из `.env.production.local` и печатает список страниц
терминала с их `uid`. Если PayPlus попросит `terminal_uid`, добавьте в тот
же файл `PAYPLUS_TERMINAL_UID`.

Тестовая и боевая среды PayPlus не связаны между собой: у каждой свои
`api-key`, `secret-key` и свой `PAYPLUS_PAGE_UID`. Боевой ключ в среде
`test` даёт 403 «API_KEY / SECRET_KEY ARE INCORRECT». Доступ к тестовой
среде выдаёт поддержка PayPlus, tech@payplus.co.il.

## Тестовые семьи

```bash
npm run families                      # завести
npm run families -- --group 'Младшие' # завести и сразу записать детей в группу
npm run families -- --remove          # удалить всё разом
```

Все тестовые родители сидят на домене `@test.re-create.art`, по нему
удаление их и находит. Дети уходят вместе с родителем, если других
опекунов у них нет. Повторный запуск ничего не дублирует.

### Bit и другие способы оплаты

Bit подключается на стороне PayPlus к самому терминалу, флагом в запросе
его не включить. Проверить, что доступно:

```bash
npm run payplus:methods
```

Команда покажет список способов и то, какие из них включены. Всё
включённое появляется на платёжной странице само. Если нужно, чтобы
какой-то способ был выбран заранее, положите его имя в
`PAYPLUS_CHARGE_DEFAULT`, например `bit`.
