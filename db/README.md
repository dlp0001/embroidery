# База

Локально Postgres поднимается докером:

```bash
docker run -d --name recreate-postgres \
  -e POSTGRES_PASSWORD=dev -e POSTGRES_USER=dev -e POSTGRES_DB=recreate \
  -p 5442:5432 postgres:18-alpine
```

Дальше схема и тестовые данные:

```bash
npm run migrate
npm run seed
```

`seed` очищает студийные таблицы и заливает четыре группы, четырёх человек
и историю посещений за месяц. На проде его запускать нельзя.

Миграции лежат в `migrations/`, применяются по имени и только один раз.
Новая миграция — новый файл с номером больше предыдущего.

## Грабли

`npm run build` пишет в ту же папку `.next`, что и `npm run dev`. Если
запустить сборку, пока дев-сервер работает, он потеряет свои чанки и
начнёт отдавать 404 на собственные стили и модули. Лечится перезапуском
дев-сервера.

## Что нужно на проде

`DATABASE_URL` и `SESSION_SECRET`. Без них разделы студии показывают
заглушку «раздел ещё не подключён», а курс по вышивке работает как
обычно.

## Neon

Один проект, одна база. Postgres 17 подходит, ничего экзотического схема
не требует: нужны расширения `citext` и `pgcrypto`, оба в Neon есть.

Регион берите ближе к людям и к деплою — для Израиля это Франкфурт
(`aws-eu-central-1`).

Neon даёт две строки подключения:

- **Pooled** (в хосте есть `-pooler`) — её кладём в `DATABASE_URL` на
  Vercel. Приложение живёт в serverless, соединений много и они короткие.
- **Direct** (без `-pooler`) — по ней гоняем миграции: DDL через пулер
  ходит хуже.

Миграции на прод:

```bash
DATABASE_URL='<direct-строка>' npm run migrate
```

`npm run seed` на проде запускать нельзя: он вычищает студийные таблицы.

Ещё нужен `SESSION_SECRET` — длинная случайная строка:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```
